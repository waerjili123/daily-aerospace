# 每日 08:00 生产推送实施计划

1. 为 workflow 事件参数建立明确映射：手动运行读取输入并默认 `dry_run`；`schedule` 固定为 `daily + 12 + dingtalk_live`。
2. 增加 `dingtalk_live` 正式投递模式：注入现有钉钉 Secrets，不添加测试标题，不执行“本轮至少一条严格已核实”测试门槛；保留钉钉 `errcode=0` 才成功的规则。
3. 将分支 guard 从仅允许验证分支调整为同时允许验证分支与 `main`，并增加北京时间 08:00 对应的 `0 0 * * *` cron。
4. 增加 workflow 与 CLI 回归测试，覆盖三种投递模式、定时参数、Secrets 边界、测试门槛和正式无严格事件发送。
5. 运行完整测试与静态检查，推送 PR #6；在 PR 分支执行一次 `dry_run`，检查报告、候选数据和运行状态，不调用钉钉。
6. 验收通过后合并 PR #6 到 `main`，核对默认分支 workflow 的 cron 与默认 dry-run；随后从 `main` 手动运行一次 `dingtalk_live` 补发 2026-08-04 日报，并以投递状态 `accepted` 确认送达。
7. 将实施、测试、合并、正式补发和下一次定时检查结果写入 `docs/PROGRESS.md`；若生产运行失败，先如实诊断，不重复盲目发送。
