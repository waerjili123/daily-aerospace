# 融资事件证据矩阵实施计划

日期：2026-07-31  
设计：`docs/superpowers/specs/2026-07-31-financing-event-evidence-matrix-design.md`

## 目标

把融资严格核验从“两个网页所有字段完全一致”改为“两个独立来源分别证明同一融资事件，
可选属性只在明确披露时保存并检查冲突”。保持官方 A 单源或两个独立注册 B 来源的严格
门槛，不把搜索日期、信息省略或推断写入正式事实。

## 任务 1：建立事件证据与属性证据边界

修改：

- `src/laser_space_daily/verifier.py`
- `tests/test_fetch_verify.py`

步骤：

1. 将单页融资检查拆分为事件必需证据和可选属性证据。
2. 双 B 来源分别要求主体、境内、商业航天业务、融资动作、轮次/子类型和页面日期证据。
3. 金额与投资方不再是确认融资事件存在的必需字段。
4. 未写金额保持空值，不生成“未披露”证据。
5. A 级官方单源保持现有完整证据规则。

验收：

- B 级页面未写金额但事件证据完整时可以参与互证。
- 页面缺主体、业务、融资动作、轮次或发布日期时仍不能参与互证。
- A 级官方单源、采购核验和既有安全规则不回退。

## 任务 2：实现轮次集合与日期邻近互证

修改：

- `src/laser_space_daily/verifier.py`
- `tests/test_fetch_verify.py`

步骤：

1. 把融资轮次解析为规范化集合。
2. 支持组合轮次与明确子轮次相容。
3. 两个单轮次不同或集合无交集时返回轮次冲突。
4. 取消两个来源发布日期必须同日的要求。
5. 使用 45 天来源发布时间窗口判断同一融资事件邻近性。
6. 日期只用于来源与事件关联，不推断融资发生日。

验收：

- “Pre-A 和 Pre-A+”与“Pre-A+”可以互证。
- “Pre-A”与“B 轮”不能互证。
- 两个来源发布日期相差 14 天可以互证，超过 45 天不能互证。

## 任务 3：实现可选属性冲突规则

修改：

- `src/laser_space_daily/verifier.py`
- `tests/test_fetch_verify.py`

步骤：

1. 一方明确金额、另一方省略时允许事件互证。
2. 双方明确金额一致时保留共同支持。
3. 双方明确金额冲突时保持待核实。
4. 投资方集合不再要求完全相同。
5. 每个 `SourceRecord` 只保存本来源自己的日期与证据。
6. 增加字段级精确诊断原因。

验收：

- 省略信息不会被解释为否定或“未披露”。
- 冲突信息不会因可选字段而被静默丢弃。
- 正式记录中的每个属性都能追溯到对应来源。

## 任务 4：流水线与诊断回归

修改：

- `src/laser_space_daily/pipeline.py`（仅在诊断映射确有需要时）
- `src/laser_space_daily/report.py`（仅在原因文案确有需要时）
- `tests/test_pipeline.py`
- `tests/test_report_notifier.py`

步骤：

1. 保持双 B 核验后的两个来源记录完整持久化。
2. 将新原因码映射为安全、可读的诊断文案。
3. 确认融资短报不显示无证据的金额或投资方。
4. 确认融资/招标硬分区与事件去重不回退。

验收：

- 端到端等价场景产生
  `verified_financing_two_independent_sources`。
- 报告只展示有逐字证据支持的可选属性。
- 候选诊断不包含正文、模型输出、请求或敏感信息。

## 任务 5：完整验证、进度和真实 dry-run

修改：

- `docs/PROGRESS.md`

步骤：

1. 运行严格核验定向测试。
2. 运行流水线和报告定向测试。
3. 运行完整离线测试。
4. 运行 `git diff --check`。
5. 检查 workflow 仍仅手动触发、默认 `dry_run`。
6. 检查基础 12、弹性 3、总上限 15 未变化。
7. 更新进度文档并提交、推送当前开发分支。
8. 由 Codex 运行一次 `dry_run`，检查报告、`run-result.json`、融资记录和诊断。
9. 若真实公开来源仍不满足矩阵，如实记录缺口，不发送钉钉。

## 总体验收

- 两个独立 B 来源分别具备事件必需证据时，可在发布日期不同、报道详略不同时严格互证。
- 金额或投资方省略不阻止事件存在的核实，也不会被推断为“未披露”。
- 不同轮次、明确金额冲突、页面日期缺失或超过 45 天仍不能晋级。
- 官方 A 单源、采购严格核验、查询预算和工作流安全边界保持不变。
- 完整测试、diff 检查和真实 `dry_run` 验收完成。
- 不发送钉钉、不修改 Secrets/可见性/workflow 状态、不合并 PR。
