# 搜索覆盖扩容实施计划

## 1. 配置与硬上限

- 将日常基础预算配置上限从 12 调整为 20。
- 将弹性核验配置上限从 3 调整为 5。
- 将日常总调用校验从 15 调整为 25。
- 更新 CLI、工作流输入和配置回归测试。

## 2. 分阶段查询计划

- 将三个采购方向的宽泛查询拆为“正在招标”和“结果公示”。
- 每个阶段增加一条官方来源定向查询。
- 日常种子查询固定保留融资 5 次、在招 6 次、结果 6 次。
- 最多补充 3 次已有项目跟踪；没有项目时由智能检索使用剩余基础预算。
- 添加查询数量、类别、阶段和预算耗尽测试。

## 3. 平衡候选选择

- 将日常最终候选上限提高到 15。
- 增加融资、在招、结果三类候选优先配额。
- 三个采购方向在在招和结果桶中各优先保留最多 2 条。
- 空余名额按现有日期、来源和相关度排序回填。
- 8—30 天候选继续补充到业务配额或总上限。
- 保持同项目不同生命周期公告共存、同阶段转载合并。

## 4. 一句话事项摘要

- 为招标短报增加只基于标题、结构化字段和搜索摘要的确定性摘要器。
- 摘要说明采购对象、采购方式或结果事项，清理站点模板和联系方式。
- 未被证据支持的采购方、金额、供应商和截止时间不得写入摘要。
- 缺少固定字段时统一显示“需核实确认”。

## 5. 验证与交付

- 运行配置、发现、流水线、报告和 workflow 定向测试。
- 运行完整离线测试、`compileall` 和 `git diff --check`。
- 更新 `docs/PROGRESS.md`。
- 提交并推送 `codex/procurement-brief-20260805`。
- 仅运行一次 GitHub Actions `dry_run`，核对搜索调用、候选配额和短报摘要；不发送钉钉。
