# 招标采购短报清晰化实施计划

## 目标

将钉钉短报的招标板块改为“可投标机会 / 需核实确认 / 结果与行业动态”三分区，使用结构化字段代替网页长标题和搜索摘要，同时保持严格核实、每日检索预算、定时投递和当天去重行为不变。

## 开发步骤

### 1. 扩展招采分析与诊断字段

修改：

- `src/laser_space_daily/models.py`
- `src/laser_space_daily/analyzer.py`
- `src/laser_space_daily/pipeline.py`

内容：

- 在分析结果中加入可选的中标/成交供应商及对应金额语义字段；
- 将公告阶段、报名/投标/开标截止时间、时间精度、截止时间证据状态和结果字段传入候选诊断；
- 保持所有新增字段可选，以兼容旧状态文件和已有测试夹具；
- 新字段必须通过页面正文或标题证据校验，禁止模型臆测。

测试：

- 模型和规则回退能提取招采阶段及截止时间；
- 中标供应商仅在正文明确披露时生成；
- 候选诊断完整保留分析字段；
- 旧 JSON 仍可正常加载。

### 2. 增加招标展示分类器

修改：

- `src/laser_space_daily/report.py`

内容：

- 建立独立的招标短报展示对象；
- 仅将公告阶段可信、投标截止时间有正文证据且未过期的项目放入“可投标机会”；
- 将疑似行动型公告但缺少截止期、官方来源或关键字段的条目放入“需核实确认”；
- 将采购意向、评审、中标候选、中标/成交、废标、终止、已关闭及已过截止期条目放入“结果与行业动态”；
- 机会按截止时间升序，待确认按行动可能性和发布日期排序，结果按公告日期倒序；
- 同一项目/事件只展示一次。

测试：

- 未截止、今日截止、已过期三类边界；
- 变更/延期提供新截止时间时可进入机会区；
- 结果类公告永不进入机会区；
- 缺证据截止时间永不进入机会区。

### 3. 实现固定字段排版与标题清洗

修改：

- `src/laser_space_daily/report.py`
- `tests/test_report_notifier.py`

内容：

- 招标板块渲染三个固定子区；
- 每条使用 2–4 行固定字段；
- 清除标题中的站点名、频道名、官网和平台重复后缀，保留项目名、标段和批次；
- 删除候选搜索摘要的直接展示；
- 金额明确标记为预算、最高限价、中标金额或成交金额；
- 链接区分官方公告、结果公告和聚合线索；
- 每区默认 3 条，长度压缩时依次降至 2 条和 1 条，关键字段和链接不截断。

测试：

- 截图所示的四川招投标长标题被清洗为项目名称；
- 联系人、电话、字号、打印、关闭和站点后缀不进入短报；
- 三个分区及可信状态均清晰可见；
- 招标预算和融资金额继续严格隔离。

### 4. 覆盖降级报告和回归验证

修改：

- `src/laser_space_daily/report.py`
- 必要的降级报告测试
- `docs/PROGRESS.md`

内容：

- 候选快照生成的降级报告复用三分区渲染规则；
- 不再把自由文本搜索摘要原样发送到钉钉；
- 更新进度文档说明新字段和分类边界。

验证命令：

- 招标渲染与分析定向测试；
- 完整测试集；
- `git diff --check`；
- 本地固定夹具 `dry_run`，检查短报长度、链接和分区；
- 推送分支并在 GitHub Actions 上执行一次 `dry_run`，不发送钉钉。

## 验收门槛

- “可投标机会”中的每条都具有未过期且有证据的投标截止时间；
- “需核实确认”明确列出缺失或冲突字段；
- 中标/成交等结果信息不会被误认为可投标；
- 不显示网页长标题或截断搜索摘要；
- 每条均有可追溯链接，金额语义不混淆；
- 全部测试通过，现有融资短报、严格核实和定时投递行为无回归。
