# 钉钉短报与融资/招标硬性分区实施计划

1. 在报告模块中建立独立的融资条目、招标条目和行业空状态渲染函数。
2. 按当前运行时窗给严格事件标注“今日新增”或“历史补录”，按可信度统一渲染
   高可信待核实和候选线索。
3. 将融资新闻固定置于招标采购之前，两个板块分别限制条目数量并独立统计。
4. 将搜索摘要压缩为短事实句，隐藏空的重点跟进和详细技术诊断。
5. 将系统状态压缩为单行；完整诊断继续通过现有 `data/` Artifact 交付。
6. 更新真实投递门禁，使其识别新的融资/招标板块且仍要求本轮至少一条严格
   已核实信息和至少一个带来源的业务条目。
7. 更新快照与报告、CLI、通知、压缩和安全相关测试，运行完整离线测试。
8. 更新进度文档并提交、推送当前分支；只执行一次 GitHub Actions `dry_run`
   验收，不发送钉钉、不合并 PR。
