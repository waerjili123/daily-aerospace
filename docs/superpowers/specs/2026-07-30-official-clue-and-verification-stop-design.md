# 官方搜索线索与弹性核验停止设计

日期：2026-07-30  
状态：待用户书面复核  
开发分支：`codex/verification-promotion-20260728`

## 1. 背景

提交 `3969d7a` 后的真实 dry-run 已运行动态弹性核验：

- 基础调用 12、弹性调用 3、总调用 15；
- 博查原始 96、主题相关 15、最终候选 5；
- 严格已核实 0、待核实 4；
- 弹性目标已从谱星航天正确切换到光邮星空；
- 三次查询各返回 10 条，但新增来源均为 0；
- 查询没有包含 `site:zgccity.com`，中关村科学城官方页面未进入抓取链路；
- 光邮星空页面逐字包含“北京光邮星空科技有限公司”，但仍返回
  `classification_country_evidence_invalid`；
- 第二、第三次仍处理同一事件，却错误标记为 `cover_distinct_target`；
- 同一运行连续两次无新增后仍执行第三次。

根因是官方域名匹配只读取模型生成的结构化 `analysis.investors`，没有把候选标题、摘要和
已落地网页证据作为搜索线索；运行内无新增次数也没有反馈给规划器。

## 2. 目标

1. 从确定性可追溯文本中识别已登记企业和投资方别名，提高官方来源查询命中率。
2. 标题、摘要和已有证据只能决定搜索方向，不能生成事实或直接升级核验状态。
3. 同页明确出现境内主体时，稳定生成逐字 `in_china` 证据。
4. 同一目标在一次运行内连续两次没有新增独立 URL 后停止继续搜索。
5. 修正弹性分配原因，使研究轨迹准确反映不同事件覆盖和同事件重试。
6. 保持基础 12、弹性最多 3、总上限 15，以及现有严格来源门槛。

## 3. 非目标与安全边界

- 不把搜索摘要、搜索发布日期或域名命中当作已核实事实。
- 不硬编码光邮星空官方页面 URL。
- 不允许单一 B 级来源或 C 级转载直接晋升。
- 不跨页面拼接 `in_china`、类别、事件、日期、轮次或金额证据。
- 不修改 Secrets、仓库可见性、workflow 启停或定时配置。
- 不设置 `dry_run=false`，不发送钉钉，不合并 PR。

## 4. 方案

采用独立的确定性搜索线索提取器，而不是要求模型稳定补全 `investors`，也不针对单个事件
固定 URL。

线索提取器只接收：

- 已有结构化主体和投资方；
- 候选标题与搜索摘要；
- 已抓取目标页面中通过逐字校验的证据；
- 配置中登记的官方企业和官方投资方域名及别名。

其输出仅为：

- 匹配到的登记域名；
- 命中的别名；
- 用于查询的主体、轮次和投资方词；
- 匹配来源类型，用于研究轨迹诊断。

输出不会写回 `AnalysisResult`，不会改变来源等级，也不会交给融资对象生成器。

## 5. 组件设计

### 5.1 官方搜索线索提取器

在 `verification_followup.py` 中增加一个独立、无网络、无模型依赖的组件。匹配顺序为：

1. 结构化主体和投资方字段；
2. 已逐字落地的目标页面证据；
3. 候选标题和摘要。

匹配仅针对配置中已经登记的完整别名。规范化允许公司法定后缀、空白、全半角括号和常见
引号差异，但不允许模糊语义推断。

当目标文本出现“中关村科学城”，且配置将该别名登记到 `zgccity.com` 时，首个官方查询
生成：

`{主体} {轮次} 融资 官网 投资机构 官方披露 site:zgccity.com 最近90天 中国境内`

如果没有登记别名命中，继续使用开放式官方查询，不猜测域名。

### 5.2 境内主体证据补全

规则分析器从同一页面标题、正文和最终 URL 中选择最短可追溯境内引文。对融资主体，优先
选择包含境内地名和完整主体名称的句段，例如“北京光邮星空科技有限公司”。

`ResilientAnalyzer` 只在主分析与规则分析对 `in_china`、范围、类别和事件结论一致时补入
规则证据。补入的每条引文必须逐字存在于目标页面；不能使用搜索摘要或其他页面。

### 5.3 运行内无新增停止

流水线为每个事件级 `target_key` 记录本次运行连续无新增次数：

- 某次查询新增至少一个规范化独立 URL：该目标计数归零；
- 某次查询新增 0：该目标计数加一；
- 达到配置的 `verification_stop_after_no_new`，默认 2：本次运行不再为该目标规划查询；
- 若存在其他合格事件，剩余预算转移给下一事件；
- 若不存在其他合格事件，停止弹性核验并保留未用预算。

持久化 `PendingItem.consecutive_no_new_sources` 继续按事件更新，并与运行内计数相加判断后续
运行是否可继续尝试。

### 5.4 分配原因

分配原因使用互斥语义：

- `official_source_match`：当前选择因已登记官方域名线索获得优先级；
- `cover_distinct_target`：目标的事件级 `target_key` 在本次运行尚未查询；
- `retry_same_target`：目标已查询过，但仍未达到停止阈值且存在未尝试查询；
- `highest_promotion_potential`：首个目标没有官方域名线索，按晋升评分选择。

只有目标事件实际发生切换时才能记录 `cover_distinct_target`。

## 6. 数据流

1. 基础发现生成候选并抓取目标页面。
2. 模型与规则分析器生成结构化结果和同页证据。
3. 首次严格核验给出精确缺口。
4. 搜索线索提取器从允许的文本层识别登记别名。
5. 规划器选择查询并记录分配原因。
6. 搜索结果进入现有相关性、抓取、分析和严格核验链路。
7. 流水线更新该事件的运行内新增计数并重新核验。
8. 规划器根据最新状态、剩余查询和停止计数决定下一次调用。
9. Artifact 输出查询、别名命中层、分配原因、查询后状态和停止原因。

## 7. 错误与降级

- 摘要命中官方别名但官方搜索无结果：保持待核实，并计入无新增次数。
- 官方结果无法抓取：记录抓取失败，不使用摘要替代正文。
- 官方正文缺少目标事实：不晋升，继续按现有证据门槛判断。
- 主分析和规则分析境内结论冲突：不补 `in_china` 证据，保持精确待核实原因。
- 连续两次无新增：停止该目标，研究轨迹记录 `no_new_source_threshold`。
- 搜索 API 失败：记录失败原因，可把剩余预算分配给其他合格事件。

## 8. 测试

### 8.1 搜索线索

- 结构化 `investors` 含登记别名时生成精确 `site:` 查询。
- 结构化投资方为空、摘要含“中关村科学城”时仍生成 `site:zgccity.com`。
- 未登记名称不能生成 `site:` 查询。
- 摘要命中不能改变 `AnalysisResult.investors` 或核验状态。

### 8.2 境内证据

- 页面含“北京光邮星空科技有限公司”时生成逐字 `in_china` 引文。
- 引文逐字存在于目标页面。
- 仅搜索摘要包含“北京”时不能补入境内证据。
- 主分析与规则分析冲突时不补证据。

### 8.3 停止与标签

- 同一运行连续两次新增 0 后不执行第三次。
- 第一次无新增、第二次新增来源时计数归零，允许第三次动态规划。
- 有第二个合格事件时，无新增目标的剩余预算转移。
- 同一目标第二次查询标记 `retry_same_target`。
- 只有实际切换到不同 `target_key` 才标记 `cover_distinct_target`。

### 8.4 回归

- 基础调用不超过 12、弹性不超过 3、总调用不超过 15。
- 官方页面仍必须通过抓取、逐字证据和来源等级校验。
- 单一 B 级、C 级转载和搜索摘要不能晋升。
- 完整离线测试和 `git diff --check` 通过。
- workflow 仍仅允许手动触发并强制 `--dry-run`。

## 9. 验收标准

代码验收：

- 光邮星空结构化投资方为空但摘要含登记别名时，生成 `site:zgccity.com` 查询；
- 页面中的“北京光邮星空科技有限公司”能够形成有效同页境内证据；
- 单目标连续两次无新增时弹性调用止于 2；
- 分配原因与实际事件切换一致；
- 严格来源和字段门槛保持不变。

真实运行验收：

- 总搜索调用不超过 15；
- 研究轨迹出现官方域名命中层和准确停止原因；
- 中关村科学城官方页面进入抓取与严格核验链路，或报告明确记录其搜索/抓取失败；
- 目标仍为至少 1 条符合既有严格标准的 `verified`；
- Actions success 不替代业务验收。
