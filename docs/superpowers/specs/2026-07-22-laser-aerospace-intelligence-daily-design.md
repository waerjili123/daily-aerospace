# 中国激光与商业航天情报日报——设计规格

日期：2026-07-22

## 1. 目标

建设一个与现有“AI日报”目录并列、内容和数据完全隔离的自动化情报项目，暂定名为“激光与商业航天情报日报”。新项目可以参考或复用原项目中与内容无关的通用能力，每天采集、核验并整理以下中国境内公开信息：

1. 激光通信相关招标及采购动态。
2. 激光武器、激光反无人机及相关系统招标动态。
3. 光电转塔、光电转台、光电吊舱及相关系统招标动态。
4. 中国商业航天企业最新一级市场融资新闻。

系统每天北京时间 07:30 运行，通过钉钉 Webhook 推送一条完整 Markdown 日报。日报顶部展示过去 24 小时新增或状态变化，随后展示滚动三个月项目池，并持续串联同一招标项目的采购全生命周期。

## 2. 非目标

- 不在现有“AI日报”中追加本项目模块，也不把 AI 新闻采集器、AI 新闻提示词、AI 新闻历史数据或 AI 日报推送内容带入新项目。
- 原“AI日报”项目保留作参考；新项目仅选择性复用调度、通知、配置加载等通用实现，并在独立目录、独立配置和独立状态库中运行。
- 不覆盖境外招标或境外航天融资。
- 不把航空飞机、无人机整机和泛低空经济融资纳入商业航天融资板块。
- 不收录普通银行授信、上市公司日常定增等非一级市场融资事件。
- 不把用途不明确的通用激光器、红外器件、伺服电机、惯导或光学材料采购纳入正式主表。
- 不允许 DeepSeek 依靠模型记忆生成事实、金额、主体或链接。
- 第一阶段不建设 Web 前端或钉钉互动卡片，只使用钉钉 Webhook 的 Markdown 消息。

## 3. 信息范围

### 3.1 招标阶段

覆盖完整采购生命周期：

- 采购意向
- 招标、询价、竞争性谈判、竞争性磋商、比选
- 更正、延期、终止
- 开标及中标候选人公示
- 中标、成交结果
- 废标及二次招标

同一项目的不同阶段保存为独立事件，但在日报主表中归并为一个项目，并展示最新状态和完整公告链。

### 3.2 激光通信

收录整机、系统以及用途明确的关键分系统，包括：

- 激光通信、空间激光通信、自由空间激光通信
- 星间、星地激光链路和激光通信终端
- 激光通信载荷
- 明确用于上述系统的光学头、通信处理模块、电源模块、一体化处理机
- 捕获、跟踪、瞄准系统
- 激光通信测试、标校和在轨验证服务

### 3.3 激光武器与反无人机

收录：

- 激光反无人机、智能激光反无设备
- 激光反制、定向能反制、高能激光毁伤
- 固定式或便携式激光枪
- 明确属于激光反制系统的雷达、光电搜索、跟踪控制和系统集成

仅含频谱侦测、无线电干扰或导航诱骗、且没有激光反制或明确光电关键分系统的项目，不归入本板块。

### 3.4 光电转塔与吊舱

收录：

- 光电转塔、光电转台、光电吊舱
- 稳瞄平台、跟踪指向器
- 多模、多光、双光吊舱
- 明确配套的可见光、红外、激光测距、伺服稳像和目标跟踪分系统
- 用途明确的吊舱结构件和结构材料

### 3.5 中国商业航天融资

企业范围覆盖中国商业航天全产业链：

- 运载火箭与发射服务
- 卫星整星、卫星载荷与核心部组件
- 卫星互联网、测运控和地面系统
- 空间数据及卫星应用
- 航天材料和用途明确的航天核心器件

融资事件范围：

- 天使轮至 Pre-IPO 股权融资
- 战略融资
- 产业基金增资
- 与一级市场融资相关的并购融资

## 4. 总体架构

```text
GitHub Actions（每天北京时间 07:30）
        ↓
DeepSeek 检索规划器
        ↓
候选发现
├─ Tavily Search API
├─ 官方网站定向采集器
└─ RSS 与行业媒体线索
        ↓
网页读取与正文提取
        ↓
来源、日期、主体与证据验证
        ↓
DeepSeek 相关性判断、结构化提取与中文整理
        ↓
确定性项目归并和生命周期更新
        ↓
仓库内 JSON/JSONL 状态数据
        ↓
Markdown 日报 → 钉钉单条推送 → 自动提交状态更新
```

模块必须通过明确接口解耦。搜索、网页读取、模型、状态存储、调度和通知均可替换，以支持后续从 GitHub Actions 迁移到自建服务器。

## 5. 检索与来源策略

### 5.1 检索方式

每天执行四类检索：

1. 过去 24 小时的新增公告和融资新闻。
2. 按历史项目编号、采购方和项目名回查状态变化。
3. 回访滚动三个月内尚未完结的项目。
4. 对已经超过投标截止日期但尚未发现结果的项目进行低频回查。

DeepSeek根据日期、板块、同义词、采购阶段和历史项目动态生成查询组合。搜索请求由 Tavily 执行，返回的真实 URL 才能进入后续流程。

第一阶段默认使用 Tavily 免费额度。系统配置每日搜索预算，优先保证过去 24 小时增量和未完结项目回查。Tavily 不可用或额度耗尽时，继续运行官方定向采集，并在日报中标明搜索覆盖降级。

### 5.2 来源分级

- A 级：政府采购网、军队采购网、公共资源交易平台、中国招标投标公共服务平台、采购方官网、企业正式公告、投资机构正式公告。
- B 级：权威财经媒体、主流媒体和专业航天媒体。
- C 级：招标聚合站、搜索摘要、自媒体及其他转载来源。

招标主表原则上只接受 A 级来源。融资事件接受企业或投资方公告；若没有正式公告，至少需要两个互相独立且可靠的 B 级来源交叉验证。C 级来源仅用于发现线索，不直接进入主表。

### 5.3 验证规则

每条正式事件必须验证：

- URL 来自搜索或定向采集工具，不是模型生成。
- 页面可以访问，或已获得可验证的正文/附件文本。
- 公告日期或融资披露日期明确。
- 标题、采购方或融资企业与正文一致。
- 金额、项目编号、轮次、投资方等关键字段能定位到证据片段。
- 信息发生在中国境内并符合板块范围。

仅有搜索摘要、原文无法访问、日期不明或主体不清的信息写入待核实队列，不进入正式日报主表。

## 6. DeepSeek 设计

### 6.1 模型分工

- `deepseek-v4-flash`：批量候选筛选、相关性判断、字段提取和普通摘要。
- `deepseek-v4-pro`：低置信度项目关联、信源冲突处理和最终趋势总结。

不使用即将弃用的 `deepseek-chat` 或 `deepseek-reasoner` 模型名称。

### 6.2 调用阶段

1. 检索规划：生成查询组合并决定是否深挖候选。
2. 候选分析：输出符合固定 JSON Schema 的相关性结论与结构化字段。
3. 关联建议：判断新事件与历史项目是同一项目、疑似相关或独立项目。
4. 日报表达：仅依据已经验证和入库的数据生成中文摘要、重点跟进和趋势。

### 6.3 约束

- 模型不得产生输入数据中不存在的 URL、金额、日期、企业、采购方或投资方。
- 所有关键字段同时保存原始证据片段和来源 URL。
- JSON 输出解析失败时重试；多次失败后进入规则降级。
- 模型建议不能越过确定性规则直接合并项目。
- 模型不可用时仍生成基础日报，并标明“AI 整理降级”。

## 7. 数据模型与持久化

GitHub Actions 环境是临时的，因此状态以 Git 友好的 JSON/JSONL 文件保存在私有仓库，并由工作流每日自动提交。

### 7.1 `events.jsonl`

每行是一条独立公开事件，核心字段包括：

- `event_id`
- `project_id`（融资事件为空）
- `event_type`
- `category`
- `title`
- `organization`
- `published_at`
- `discovered_at`
- `amount`
- `source_url`
- `source_domain`
- `source_grade`
- `evidence`
- `content_hash`
- `verification_status`

### 7.2 `projects.json`

保存招标项目的最新状态：

- `project_id`
- 规范化项目名
- 采购方
- 项目编号及采购编号集合
- 类别与关键分系统标签
- 当前阶段和当前状态
- 金额或预算
- 首次公开时间与最新动态时间
- 报名、投标、开标等关键期限
- 事件 ID 列表
- 最新公告 URL
- 是否仍需回查

### 7.3 `financings.json`

保存融资事件：

- 企业规范名
- 公告日期
- 轮次
- 金额及是否披露
- 投资方
- 业务方向
- 来源链和证据
- 去重指纹

### 7.4 `pending.json`

保存无法充分验证、疑似重复、来源冲突或需要人工判断的线索及原因。

## 8. 项目串联与去重

### 8.1 招标项目

最终归并优先级：

1. 完全相同的项目编号或采购编号。
2. 采购方相同且规范化项目名相同。
3. 采购方相同、标题高度相似，且时间和采购阶段能够合理衔接。
4. DeepSeek 建议为同一项目，但证据不足时标记为疑似关联，等待复核。

不同年度、不同批次或不同标段默认视为独立项目。“二次”“重新招标”作为原项目的新事件，但保留各自公告信息。废标后允许进入二次招标和重新评标分支。

### 8.2 融资事件

按企业规范名、轮次、公告日期、金额和投资方生成去重指纹。媒体转载不产生新融资事件。不同信源金额冲突时不自行猜测，写明“金额未完全披露”或“信源数据不一致”。

### 8.3 时间窗口

- 过去 24 小时内的新事件或状态变化进入日报顶部。
- 最新动态发生在三个月内的项目保留在滚动项目池。
- 超过三个月的项目转入历史数据，不再进入钉钉正文，但仍参与未来匹配。

## 9. 日报输出

钉钉使用单条 Markdown 消息，不依赖 HTML、CSS 表格或互动卡片。稳定支持标题、粗体、列表和直接链接。

模块顺序：

1. 标题、统计日期和覆盖状态。
2. 过去 24 小时新增或状态变化。
3. 当前可报名及即将启动项目。
4. 滚动三个月项目池：激光通信、激光武器/反无人机、光电转塔/吊舱。
5. 中国商业航天融资。
6. 今日重点跟进。
7. 三个月趋势和数据完整性说明。

新增事件采用详细字段展示；滚动项目池采用紧凑条目，避免消息过长。接近钉钉长度上限时，优先压缩已经完结的历史项目描述，但必须保留全部 24 小时变化、当前可报名项目、即将启动项目和融资事件。

链接直接指向原始网页。同一招标项目按实际存在的阶段显示公告链：

```markdown
[采购意向]｜[招标公告]｜[更正公告]｜[候选人公示]｜[中标结果]
```

融资事件按可靠性显示：

```markdown
[企业公告]｜[投资方公告]｜[权威媒体报道]
```

## 10. 调度、配置与安全

第一阶段使用 GitHub Actions：

- 定时表达式对应北京时间每日 07:30。
- 支持 `workflow_dispatch` 手动运行。
- 使用并发锁，避免同一日期重复执行。
- 手动运行默认支持 `dry-run`，只生成日报而不推送。
- 正式任务成功后提交状态文件和当日日报。

敏感信息仅保存为 GitHub Actions Secrets：

- `DEEPSEEK_API_KEY`
- `TAVILY_API_KEY`
- `DINGTALK_WEBHOOK`

密钥不得写入配置、日志、日报、测试样本或 Git 历史。

## 11. 容错与可观测性

- 单一来源失败不终止其他来源。
- Tavily 失败时继续官方定向采集。
- DeepSeek 失败时启用规则降级。
- 页面无法验证时进入待核实队列。
- 同日重跑保持幂等，不重复创建事件。
- 钉钉推送失败时保存完整 Markdown 和日志，并使 Actions 任务失败。
- 数据提交失败时保留生成产物并明确报警。

每次运行记录：

- 搜索次数
- 候选数量
- 验证通过数量
- 待核实数量
- 新建项目数
- 状态更新项目数
- 去重数量
- 失败来源
- DeepSeek Token 用量
- 搜索额度使用量

## 12. 测试策略

### 12.1 单元测试

覆盖关键词匹配、日期解析、金额规范化、项目编号提取、URL 验证、内容哈希和确定性去重。

### 12.2 固定样本测试

保存脱敏且不含密钥的真实公告与融资页面样本，验证正文提取、字段映射、来源分级和项目串联。

### 12.3 模型契约测试

使用模拟响应检查 JSON Schema、缺失字段、错误字段、禁止生成 URL 和重试/降级逻辑。常规测试不得依赖真实 DeepSeek 调用。

### 12.4 Markdown 快照测试

验证模块顺序、直接链接、公告链、状态标识和长度控制，确保钉钉显示稳定。

### 12.5 端到端测试

通过 GitHub Actions 手动触发 `dry-run`，完成搜索、抓取、验证、整理和日报生成，但不向正式钉钉群推送。确认结果后再启用定时推送。

## 13. 服务器迁移

后续迁移到服务器时：

- GitHub Actions 调度替换为 cron 或服务调度器。
- JSON/JSONL 状态可导入 SQLite 或 PostgreSQL。
- 搜索、读取、验证、DeepSeek、归并和渲染模块保持不变。
- 可增加浏览器补采器处理云端 IP、动态页面、验证码或登录限制。
- 迁移期间保持同一项目 ID 与事件 ID，避免历史断链。

## 14. 验收标准

1. 每天北京时间 07:30 自动运行并发送一条钉钉 Markdown 消息。
2. 正确展示过去 24 小时变化和滚动三个月项目池。
3. 同一项目的意向、招标、变更、废标、二次招标及结果能够串联。
4. 每条正式信息都有可点击的真实来源及关键字段证据。
5. 主表不包含仅由模型生成或无法验证的信息。
6. 融资范围严格限定中国商业航天一级市场。
7. 外部服务故障时有明确降级、待核实或失败提示。
8. 同日重复运行不产生重复事件或重复项目。
9. 密钥不会出现在代码、日志、日报或 Git 历史中。
10. 项目能够从 GitHub Actions 平滑迁移到自建服务器。
