# 智能多轮情报检索设计

日期：2026-07-28（北京时间）

## 1. 目标

将当前“四个固定查询＋单页分析”的采集方式升级为有严格预算上限的智能多轮检索：

- DeepSeek 负责制定查询、识别线索和决定追查方向；
- 博查负责执行网页搜索；
- 本地代码负责预算控制、正文抓取、事件过滤、去重、证据核验和报告生成；
- 在不降低事实标准的前提下，提高具体采购、项目状态和融资事件的覆盖率。

目标不是复刻或自动操作 DeepSeek 网页版，而是使用官方 DeepSeek API 的 Tool Calling 能力，在现有系统内构建可测试、可审计的研究循环。

## 2. 非目标与安全边界

本阶段不包含：

- 不恢复或启用 schedule；
- 不发送钉钉；
- 不执行 `dry_run=false`；
- 不合并 PR #4 或 PR #5；
- 不修改 GitHub Secrets；
- 不修改仓库可见性；
- 不关闭 TLS 校验；
- 不通过浏览器自动化调用 DeepSeek 消费者网页；
- 不允许模型突破搜索预算或直接写入正式状态。

## 3. 方案选择

采用方案 A：DeepSeek Tool Calling 多轮检索。

未采用：

- 仅扩充固定关键词：无法根据项目名、采购方和公告编号动态追查；
- 自动操作网页版：登录、验证码、页面变化及平台规则不适合无人值守生产流程。

## 4. 总体架构

```text
研究任务
  ↓
AgenticSearchOrchestrator
  ├─ DeepSeek：生成查询与下一步动作
  ├─ BochaSearchTool：执行搜索
  ├─ BudgetGuard：限制调用次数和轮次
  └─ ResearchTrace：记录查询、结果和停止原因
  ↓
事件意图过滤
  ↓
事件级近重复合并
  ↓
正文抓取与 DeepSeek 单页结构化分析
  ↓
确定性证据核验
  ↓
已核实事件 / 待核实线索 / 普通候选
  ↓
分类日报与 Artifact
```

模型只提出工具调用和结构化研究结论。所有外部请求、预算、数据落库和正式状态变更由本地代码控制。

## 5. 两种运行模式

### 5.1 日常增量

- 搜索预算硬上限：12 次博查调用；
- 覆盖窗口：近 7 天优先，可追查近 30 天项目状态；
- 四个板块各至少保留一次种子搜索机会；
- 剩余预算由模型用于项目名、采购方、公告编号、状态变化及第二来源追查；
- 达到预算、连续无新增或模型给出完成信号时停止。

### 5.2 历史回填

- 搜索预算硬上限：40 次博查调用；
- 覆盖窗口：近 90 天；
- 必须强制 dry-run；
- 不发送钉钉，不启用 schedule；
- 产出独立 Artifact，供人工审核后再决定是否写入长期项目池。

日常增量和历史回填使用相同的检索、过滤、去重和核验组件，仅预算、时间窗口和输出策略不同。

## 6. 工具接口

### 6.1 `search_web`

输入：

- `query`：搜索语句；
- `category`：四个板块之一；
- `intent`：种子搜索、项目追踪、状态追踪或交叉核验；
- `freshness`：与运行模式一致的时间范围；
- `count`：受本地配置限制的单次结果数。

输出：

- 标题；
- URL；
- 搜索摘要；
- 搜索引擎提供的发布日期；
- 分类提示；
- 查询和意图标识。

本地代码负责：

- 拒绝空查询、超长查询和重复查询；
- 限制板块范围；
- 强制时间范围；
- 原子化扣减预算；
- 规范化和记录返回数据；
- 对 API 错误进行分类。

### 6.2 模型研究动作

DeepSeek 可以：

- 提出新的搜索查询；
- 指定要追查的项目、采购方、企业或公告编号；
- 请求寻找第二来源；
- 判断当前研究是否可以停止。

DeepSeek 不可以：

- 直接访问网络；
- 更改预算；
- 指定任意未批准工具；
- 将候选直接标记为已核实；
- 写入仓库或发送通知。

首版只向模型开放 `search_web`。正文抓取仍在候选选择后由现有抓取器批量执行，避免模型无限制读取网页。

## 7. 搜索策略

四个板块的种子任务：

- 激光通信：采购意向、招标、询价、比选、变更、候选人、中标、交付；
- 激光武器/反无人机：采购、招标、测试、交付和项目状态；
- 光电转塔/吊舱：采购、招标、候选人、中标和交付；
- 商业航天融资：融资完成、增资、投资方公告、公司公告。

追查优先级：

1. 公告编号；
2. 完整项目名；
3. 项目名＋采购方；
4. 企业名＋融资轮次或投资方；
5. 项目状态关键词；
6. 第二独立来源。

每次搜索结果会回传给模型，模型可据此生成下一轮查询。系统拒绝语义完全相同或规范化后相同的重复查询。

## 8. 事件意图过滤

候选必须同时满足板块主题和具体事件意图。

排除：

- 行业研究报告及报告销售页；
- 打印版、目录页和同一报告镜像页；
- A 股行情、概念板块涨跌和荐股内容；
- 券商泛化行业观点；
- 没有具体主体和事件的趋势评论；
- 已有打印机、美容、通用医疗用品和无关软件噪声；
- 商业航天银行贷款、授信及上市公司常规再融资。

采购类事件至少包含一个采购生命周期信号。融资类事件至少包含商业航天主体和股权融资事件信号。

## 9. 事件级近重复合并

URL 规范化去重继续保留，并增加事件级近重复判断。

判定信号：

- 规范化标题；
- 板块；
- 采购方、企业或项目主体；
- 公告编号；
- 事件类型；
- 来源日期；
- 摘要关键词。

规则：

- 相同公告编号视为同一事件；
- 同一主体、同一事件类型、日期相近且标题高度相似时合并；
- 普通页、打印页和转载页合并为一个候选，保留全部来源 URL；
- 同一项目的招标、中标、变更和终止属于不同生命周期事件，不合并；
- 无法确定时宁可保留两条，不进行激进合并。

首版采用确定性文本相似度和字段规则，不引入向量数据库。

## 10. 来源和核验等级

来源优先级：

1. 政府、军队、公共资源及法定招标平台；
2. 采购方、企业或投资方官方公告；
3. 权威媒体和可信财经媒体；
4. 搜索摘要、转载和聚合页面。

输出状态：

- 已核实：满足现有证据规则；
- 待核实：事件相关但正文、主体、日期或第二来源不足；
- 普通候选：通过搜索门槛但不足以进入待核实池；
- 已拒绝：研报销售页、行情评论、泛化观点或其他范围外内容。

官方正文打不开时，可以保留搜索摘要为待核实线索，但不能进入已核实事件。

## 11. 报告口径

四个分类板块：

- 优先展示已核实事件；
- 可附带本板块“候选线索（未核实）”；
- 每条线索明确展示状态，不与正式事件混排；
- 同一候选不再在“今日重点跟进”重复出现。

“今日重点跟进”只保留：

- 报名或投标截止；
- 即将启动；
- 状态发生变化；
- 需要人工核验的最高价值线索。

三个月趋势区增加：

- 智能搜索轮次；
- 博查预算与实际消耗；
- 重复查询拦截数；
- 事件过滤淘汰数；
- 事件级合并数；
- AI 工具调用失败原因；
- 停止原因。

## 12. 降级策略

DeepSeek 规划不可用时：

- 退回现有四个确定性种子查询；
- 保持预算和时间窗口；
- 报告标注“智能检索降级”。

博查不可用时：

- 记录认证、配额、限流、服务器或网络错误；
- 不生成虚假候选；
- 保留官方来源采集结果。

模型单页分析不可用时：

- 使用现有保守规则分析；
- 报告区分“规划降级”和“分析降级”；
- 记录错误类别，不记录密钥、完整正文或敏感请求。

## 13. 配置与兼容性

新增配置：

- `discovery.mode`：`daily` 或 `backfill`；
- `discovery.daily_search_budget`：默认 12，最大 12；
- `discovery.backfill_search_budget`：默认 40，最大 40；
- `discovery.max_agent_rounds`；
- `discovery.max_results_per_call`；
- `discovery.stop_after_no_new_rounds`；
- 事件过滤和近重复阈值。

保持：

- DeepSeek 和博查使用现有 Secrets；
- 当前数据 schema 不在首版修改；
- 当前 CLI 默认仍为日常模式；
- workflow 默认强制 dry-run；
- 现有固定查询作为降级路径。

## 14. 可观测性

Artifact 中保存不含敏感信息的研究轨迹：

- 每轮动作类型；
- 查询文本；
- 板块和意图；
- 返回数量；
- 新增候选数量；
- 剩余预算；
- 工具错误类别；
- 停止原因。

不得保存：

- API Key；
- 钉钉 Secret；
- 请求认证头；
- 未裁剪的完整模型输入和网页正文；
- 模型隐藏推理内容。

## 15. 测试

离线测试覆盖：

- 日常预算不超过 12；
- 回填预算不超过 40；
- 四板块种子搜索公平性；
- 重复查询不扣减或不重复执行；
- 达到预算立即停止；
- 连续无新增提前停止；
- Tool Calling JSON 校验；
- DeepSeek 失败后固定查询降级；
- 研报、股市评论、券商观点排除；
- 普通页与打印页合并；
- 生命周期不同事件不误合并；
- 正式事件、待核实和普通候选隔离；
- 日报候选不重复展示；
- 日志和 Artifact 不泄露 Secrets。

回归要求：

- 完整离线测试通过；
- `git diff --check` 通过；
- 不改变 schedule、Secrets、仓库可见性或通知状态。

## 16. 验收流程

1. 完成离线实现与固定样本测试；
2. 运行一次 40 查询历史回填 dry-run；
3. 人工审核近 90 天项目池、来源、重复和噪声；
4. 运行一次 12 查询日常 dry-run；
5. 验收以下指标：
   - 研报销售页、股市评论和泛化券商观点为 0；
   - 同一报告普通页与打印页不重复；
   - 至少形成可审阅的具体事件线索；
   - 正式事件仍满足原有证据标准；
   - 搜索和 AI 降级原因可定位；
6. 质量达标后再讨论 PR 合并、钉钉发送和北京时间 07:30 定时任务。
