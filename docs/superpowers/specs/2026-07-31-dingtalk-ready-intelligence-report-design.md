# 可直接钉钉推送的情报日报设计

## 目标

日报必须把“严格已核实”“高可信待核实”“候选线索”分层展示，不再因严格核验数为零而表现为空。手动工作流默认 dry-run；只有显式选择 `dingtalk_test` 才使用现有 Secrets 发送一次带“【测试】”标识的消息。

## 数据与核验

- 网页元数据、JSON-LD 或可见页头给出的发布日期，在与分析日期一致时补充为 `published_at` 证据；冲突时不覆盖。
- 融资主体从全部候选语句中评分选择，剥离行业描述、地域、公司法律后缀和新闻话术，拒绝动作短语充当主体。
- 同一主体、融资轮次一致且金额或投资方相容的报道按 30 天窗口归为同一核验事件；其他事件仍使用 7 天窗口。
- 弹性检索优先尝试尚未出现的注册 B 级媒体域名，预算保持基础 12、弹性 3、总计最多 15。
- 未明确写出“金额未披露”的来源不得支持 `amount_disclosed=false`。

## 报告

- 标题后增加“今日最值得看”，最多三条，优先级为严格已核实、高可信待核实、普通候选。
- 分类板块直接展示相应待核实线索，每个事件只展示一次，包含日期、主体或标题、明确金额、状态和来源。
- 高可信待核实只表示结构化事实较完整且来源为 A/B，或同一事件已有两个独立来源但仍缺少严格字段；它不是已核实。
- 报告继续受 18,000 字符上限保护，摘要压缩到适合钉钉阅读的长度。

## 失败兜底与投递

- Pipeline 在完成抓取和分析后写入本轮候选检查点。
- 后续阶段失败时，CLI 从检查点生成“【降级】”快报并尝试投递；投递成功后进程仍以失败退出，Actions 如实显示失败。
- 检查点产生前失败时，仅发送“【异常】”运行告警，不伪造情报。
- `run-result.json` 与 `delivery-status.json` 分别记录业务状态和投递状态，不包含 webhook、签名或 Secret。
- DingTalk 仅在 HTTP 成功且响应 `errcode=0` 时视为送达。

## 边界

不合并 PR，不修改 Secrets、仓库可见性或 workflow 启停状态；工作流保持仅手动触发，默认 dry-run。
