# 融资事件证据矩阵设计

日期：2026-07-31  
状态：已获用户书面复核确认  
开发分支：`codex/verification-promotion-20260728`

## 1. 背景与根因

Actions #36 已能稳定生成融资与招标硬分区短报，但严格已核实为 0。真实诊断中，
光邮星空同一融资事件已经出现投资界与投中网两个独立 B 级来源，仍停留在
`financing_missing_required_evidence`。

代码核对确认，现有“双 B 来源”判定把来源之间的信息详略和网页属性误当成事件事实：

- 每篇报道都必须提供金额证据；页面未写金额时不能进入来源互证；
- 两个来源的网页发布日期必须完全相同；
- 融资轮次字符串必须完全相同；
- 投资方集合必须完全相同。

这些要求会误拒同一事件的独立报道。例如，一篇报道“Pre-A 和 Pre-A+”，另一篇只聚焦
“Pre-A+”；或一篇列出全部投资方，另一篇省略部分投资方。另一方面，直接删除这些检查
会产生跨轮次误合并或把未披露事实写入正式记录的风险。

## 2. 目标

采用“事件必需字段 + 可选属性字段”的证据矩阵：

1. 两个独立 B 级页面分别证明同一境内商业航天企业发生了融资事件。
2. 来源网页发布时间只证明该来源的发布时间，不要求两个媒体同日发布。
3. 组合轮次与其明确子轮次可以互证；互不相交的轮次不能互证。
4. 金额和投资方只在页面明确披露时保存；页面未写不等于“未披露”。
5. 双方明确披露的关键属性发生冲突时，事件保持待核实。
6. 不改变官方 A 单源或两个独立注册 B 来源的严格来源门槛。

## 3. 非目标与安全边界

- 不新增或降低 A/B/C 来源等级。
- 不使用搜索摘要、搜索日期、抓取时间或 URL 日期补齐严格事实。
- 不把“页面没有写金额”解释为“金额未披露”。
- 不把一篇报道的金额、投资方或日期复制到另一篇来源的证据记录。
- 不允许两个互不相交的融资轮次归为同一事件。
- 不改变基础 12、弹性最多 3、总计最多 15 的查询上限。
- 不修改 Secrets、仓库可见性、workflow 启停或定时配置。
- 不合并 PR，不发送钉钉；本阶段真实验证仅运行 `dry_run`。

## 4. 方案选择

采用字段分层的事件互证。

未采用的方案：

- **继续补搜直到所有字段完全相同**：不改变代码语义，但真实媒体经常省略金额或部分
  投资方，15 次硬上限内仍会长期无法核实。
- **只接受企业或投资方官网**：最保守，但商业航天融资的官方披露并不稳定，日报会长期
  稀疏。
- **整体放宽双 B 判定**：命中率高，但无法阻止不同轮次或冲突金额被错误合并。

字段分层保留两个独立 B 级来源和逐页证据要求，只修正“哪些字段用于确认事件存在”和
“哪些字段只是事件属性”。

## 5. 证据矩阵

### 5.1 每个来源必须独立满足

每个参与互证的 B 级页面必须分别具备：

- 页面可访问且内容哈希不同；
- 注册域名独立；
- 境内主体逐字证据；
- 商业航天业务逐字证据；
- 融资动作逐字证据；
- 企业主体逐字证据；
- 融资轮次或明确融资子类型逐字证据；
- 页面自身的可核验发布日期及其逐字证据；
- 页面事实与结构化分析一致。

任一来源缺少上述字段时，不得参与双 B 严格互证。

### 5.2 来源之间必须一致或相容

两个来源必须满足：

- 规范化企业主体相同；
- 融资子类型相同；
- 轮次集合有交集，或一方组合轮次包含另一方单轮次；
- 两个网页发布时间位于同一融资事件的 45 天邻近窗口内；
- 双方明确披露金额时，规范化金额一致；
- 双方明确披露同一角色的投资方信息时，不存在可确定的排他性冲突。

网页发布时间不作为融资发生日。45 天窗口只用于判断两篇报道是否可能描述同一事件，
不会写入或推断事件日期。

### 5.3 可选属性字段

以下字段不再作为“融资事件存在”的必需条件：

- 金额；
- 投资方；
- 业务用途；
- 估值；
- 融资发生日。

保存规则：

- 只有页面明确披露且存在逐字证据时才保存。
- 一方披露、另一方省略时，允许确认事件存在；该属性保留披露来源的证据归属。
- 双方都披露且值一致时，可聚合为共同支持的属性。
- 双方都披露且值冲突时，整个事件保持待核实，并记录精确冲突原因。
- 双方都未披露时，字段保持空值，报告不显示该字段。

### 5.4 轮次相容规则

轮次先解析为规范化集合，例如：

- `Pre-A 和 Pre-A+` → `{pre-a, pre-a+}`
- `Pre-A+轮` → `{pre-a+}`

判定：

- 集合相等：相容；
- 一个集合包含另一个集合：相容；
- 集合有交集且一方明确为连续/组合融资：相容；
- 两个单轮次不同，或集合完全不相交：冲突；
- 任一方缺少轮次且也没有明确融资子类型：证据不足。

组合轮次互证只确认共同交集部分。正式记录可保留有逐字证据支持的组合表述，但不得把
另一来源未提及的轮次标记为双方共同确认。

### 5.5 日期规则

`published_at` 继续表示来源网页发布时间：

- 每个来源必须分别提供自己的页面发布日期证据；
- 两个来源无需同日；
- 相差不超过 45 天才进入同事件互证；
- 超过 45 天时保持独立事件或待核实，不自动合并；
- 页面日期冲突、缺失或仅来自搜索元数据时，该来源不能参与严格互证。

## 6. 组件与数据流

### 6.1 Verifier

将现有单一 `_financing_claim_failure` 拆分为两个职责：

1. `source_event_evidence_failure`：检查单个页面是否独立证明主体、业务、融资动作、
   轮次/子类型和页面发布日期；
2. `financing_attribute_conflicts`：比较两个来源明确披露的金额、轮次和其他可选属性。

单源 A 级官方核验仍使用完整逐页证据，不受双 B 互证矩阵影响。

### 6.2 Corroboration

双 B 互证流程：

1. 校验独立域名与不同内容哈希；
2. 分别执行来源级事件证据检查；
3. 规范化主体并比较；
4. 使用轮次集合判断相容性；
5. 使用 45 天网页发布时间窗口判断事件邻近性；
6. 比较双方明确披露的可选属性；
7. 无冲突时生成 `verified_financing_two_independent_sources`；
8. 保存两个独立 `SourceRecord`，各自保留自己的日期和逐字证据。

### 6.3 诊断

新增或细化安全诊断原因：

- `financing_source_event_evidence_missing`
- `financing_corroboration_date_outside_window`
- `financing_corroboration_round_conflict`
- `financing_corroboration_amount_conflict`
- `financing_corroboration_attribute_conflict`

诊断只记录字段名、原因码、来源域名和证据数量，不记录正文、模型原始输出、请求内容或
敏感信息。

## 7. 错误处理

- 来源缺必需事件证据：保持 pending，不进入互证。
- 来源只有搜索日期：保持 pending，不用搜索日期补齐。
- 组合轮次无法解析：保持 pending，不按字符串模糊包含强行合并。
- 双方金额一个明确、一个省略：允许互证，金额只保留在披露来源。
- 双方金额明确冲突：保持 pending。
- 双方投资方列表详略不同：不要求集合完全一致；只保存各自证据，不补齐另一来源。
- 日期超过 45 天：不视为同一融资事件。
- 真实 dry-run 仍为 0 条严格已核实：如实保留结果并输出剩余证据缺口，不发送钉钉。

## 8. 测试设计

### 8.1 应严格通过

- 两个独立 B 来源，同一企业、同一 Pre-A+，网页发布日期相差 14 天，一方未写金额。
- 一个来源写“Pre-A 和 Pre-A+”，另一个只写“Pre-A+”，其他必需事实一致。
- 一方列出多个投资方，另一方只列领投方或不列投资方。
- 一方明确披露金额，另一方省略金额；正式字段仅保留有证据的金额。

### 8.2 应保持待核实

- 两个来源分别写 Pre-A 与 B 轮。
- 两个来源明确金额不一致。
- 两个来源网页发布日期相差超过 45 天。
- 任一来源缺少页面发布日期证据。
- 任一来源缺少企业主体、商业航天业务或融资动作证据。
- 一个来源是 C 级转载，或两个 URL 属于同一注册域名。

### 8.3 回归与安全

- A 级官方融资单源核验保持原有严格行为。
- 采购招标严格核验不受影响。
- “未写金额”不会变成 `amount_disclosed=False`。
- SourceRecord 各自保留自己的发布日期和证据。
- 候选合并、短报融资/招标硬分区和链接不回退。
- 完整离线测试、`git diff --check` 与 workflow 安全检查通过。
- workflow 仍仅手动触发，默认 `dry_run`。

## 9. 验收标准

代码验收：

- 光邮星空等价场景可由两个独立 B 来源严格核实；
- 不同发布日期和报道详略不再被误判为事实冲突；
- 不同轮次、冲突金额和缺失页面日期仍不能晋级；
- 所有正式属性都有来源级逐字证据；
- 全部既有测试和新增证据矩阵测试通过。

真实运行验收：

- 使用当前分支执行一次 `dry_run`；
- 基础查询不超过 12、弹性不超过 3、总计不超过 15；
- 若真实来源满足矩阵，至少产生 1 条严格已核实融资；
- 报告中融资和招标仍硬性分区，条目带可追溯链接且无重复；
- 若真实来源仍不满足矩阵，报告准确显示剩余缺口，不把 Actions success 当作业务成功；
- 不发送钉钉，不修改 Secrets、可见性、workflow 状态，也不合并 PR。
