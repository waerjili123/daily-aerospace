# 严格核验来源与页面证据修复设计

日期：2026-07-30
状态：待用户书面复核
开发分支：`codex/verification-promotion-20260728`

## 1. 背景

提交 `b2c0d3d` 后的最新真实 dry-run Artifact
`daily-intelligence-report (6).zip` 显示：

- 基础检索 12 次、弹性核验 3 次、总调用 15 次；
- 博查原始 99 条、主题相关 22 条、最终候选 5 条；
- 严格已核实 0 条、待核实 5 条；
- `candidate-diagnostics.json` 正常生成，共记录 10 条进入抓取链路的候选；
- 5 条候选保持 pending，另外 5 条在核验阶段因 `out_of_scope` 被拒绝；
- 3 次弹性核验只覆盖“光邮星空”同一融资事件的两个页面，其中一个页面被查询两次；
- 弹性核验新增来源 1 条、重复来源 29 条；另外 3 个具备弹性资格的候选没有获得预算。

对真实候选页面使用生产抓取器复现后，确认存在四个相互关联的根因：

1. `trafilatura` 提取正文时会丢掉标题附近的可见发布时间。网页本身明确显示完整
   年月日，但进入分析器的 `FetchedPage.text` 不包含该时间，最终被判定为
   `missing_required_fields:published_at`。
2. 规则分析器使用整篇文章判断境内外。国内商业航天长文只要在后文比较 SpaceX，
   就可能被“境外信号”整体否决，即使标题和导语已经明确写出北京企业及境内融资。
3. 弹性规划器虽然配置 `verification_max_targets: 3`，但首次覆盖逻辑实际只保证两个
   不同目标；真实数据中的公司全称、简称或融资轮次差异还会让同一事件产生不同目标键。
4. 同事件来源按发布时间优先选主来源和补充来源，更新稍晚的 C 级转载可能挤掉已经登记的
   B 级媒体，导致严格双 B 来源核验没有机会执行。

本轮不是扩大抓取数量，而是修复页面事实进入严格核验链路的方式，以及有限弹性预算和
高等级来源的选择方式。

## 2. 目标

1. 保留网页自身标题区或署名区明确展示的完整发布时间，并形成可逐字核验的页面证据。
2. 让境内外判断围绕事件主体，而不是被正文后部的国外比较对象误导。
3. 将同一事件的公司全称、简称和多来源页面统一为同一个弹性核验目标。
4. 3 次弹性预算优先覆盖最多 3 个不同事件，覆盖完成前不重试同一事件。
5. 同事件优先保留官方 A 级或已登记 B 级来源，再比较时效性和相关性。
6. 将专业创投媒体投中网 `chinaventure.com.cn` 登记为 B 级来源。
7. 保持“官方 A 级单源，或两个独立 B 级来源相互印证”的严格晋级门槛。
8. 在离线端到端回归中产生至少 1 条符合严格规则的 `verified` 融资事件，并在下一次
   真实 dry-run Artifact 中以至少 1 条严格 `verified` 作为业务验收目标。

## 3. 非目标与安全边界

- 不把博查 `datePublished`、搜索摘要日期、URL 日期或抓取时间写入
  `AnalysisResult.published_at`。
- 不允许 C 级来源单独晋级，也不把普通转载站批量提升为 B 级。
- 不把东方财富、新浪、腾讯等转载域名在本轮批量登记为 B 级。
- 不降低融资金额、轮次、主体、类别、事件类型或逐字证据要求。
- 不改变基础 12、弹性最多 3、总计最多 15 的调用预算。
- 不实现跨 Actions 的 Artifact 状态回灌。
- 不修改仓库可见性、Secrets、workflow 启停或定时配置。
- 不设置 `dry_run=false`，不发送钉钉，不合并 PR。

## 4. 方案选择

采用完整证据链修复：

1. 页面级可见发布时间提取；
2. 事件主体级境内外判断；
3. 稳定的事件指纹和三目标预算覆盖；
4. 来源等级感知的主来源及补充来源选择；
5. 窄范围新增投中网 B 级来源。

未采用：

- **仅补日期和来源配置**：改动较小，但同一事件仍可能占满预算，C 级转载仍会挤掉
  B 级来源，真实结果不稳定。
- **仅依赖官方来源**：门槛最保守，但当前政府采购站点访问失败率较高，无法解决商业航天
  融资主要通过企业、投资机构和专业媒体披露的现实情况。
- **批量扩充 B 级媒体或采用搜索日期**：命中率高，但容易把转载当独立来源，或把搜索
  元数据误写成事实，不符合严格核验目标。

## 5. 组件设计

### 5.1 页面发布时间证据

抓取器新增结构化、瞬态的页面发布时间证据：

- `publication_date_quote`
- `publication_date_source`

`publication_date_source` 仅允许：

- `metadata`
- `json_ld`
- `visible_header`

提取优先级：

1. 现有 `article:published_time`、`datePublished` 等明确发布元数据；
2. JSON-LD 中的 `datePublished`；
3. 文章标题、作者、署名或公告属性区域内的可见发布时间。

可见发布时间必须满足全部条件：

- 包含完整四位年份、月份和日期；
- 位于文章标题或署名区域，或带有“发布日期”“发布时间”等明确标签；
- 元素自身或近邻结构具有 `publish`、`release`、`article`、`date`、`time` 等
  语义标识；
- 不是“更新时间”“最后修改”“相关文章”“历史文章”或页脚日期。

禁止使用“扫描整页后取第一个日期”的方式，避免把正文中的历史日期或相关推荐日期当成
当前文章发布日期。

当严格日期证据未被正文抽取器保留时，抓取器把如下逐字文本追加到
`FetchedPage.text`：

```text
页面发布时间：<原始日期文本>
```

规则分析器和模型 grounding 继续只基于 `FetchedPage.title` 与
`FetchedPage.text`。因此新增日期仍来自目标网页本身，而不是搜索结果回填。

### 5.2 事件主体级境内外判断

新增统一的“事件主体上下文”选择函数，供规则分析器和严格核验分类一致性检查共同使用。

主体上下文包括：

- 页面标题；
- 导语和最前面的有限行；
- 同时包含候选主体与融资、采购或招中标动作的句子；
- 明确写出企业全称、采购方或研究机构的句子。

判断规则：

1. 主体上下文明确出现境内企业或机构时，正文后部单独出现 SpaceX、海外市场或国外
   技术比较，不再否决境内结论。
2. 标题、导语或事件动作句明确指向国外主体时，仍判定为非境内。
3. 只有正文背景出现“中国市场”而事件主体明确为国外企业时，不能判定为境内。
4. 规则分析器和 verifier 必须使用同一主体上下文，避免主分析通过但分类一致性检查
   再次误拒。

本设计只改变境内外信号的作用范围，不以域名、搜索摘要或候选标签替代主体证据。

### 5.3 弹性核验事件指纹

新增统一的 `verification_event_key`，用于：

- 合并同事件不同 URL；
- 记录弹性目标是否已覆盖；
- 维护连续无新增次数；
- 输出候选诊断。

融资事件指纹由以下确定性字段组成：

- 规范化主体别名；
- 类别；
- 事件类型；
- 规范化融资轮次集合；
- 候选页面日期的有限时间邻近关系。

主体规范化规则：

- 去除“有限责任公司”“股份有限公司”等注册后缀；
- 优先使用页面明确给出的简称；
- 公司全称包含且页面标题明确使用简称时，以该简称作为事件主体；
- 不通过任意删除“北京”“上海”“科技”等普通词推造简称。

融资轮次规则：

- 从结构化分析和候选标题中提取全部明确轮次；
- “连续完成 Pre-A 和 Pre-A+”的不同表述使用同一轮次集合；
- 两方页面日期相差不超过 7 个自然日，才视为日期邻近；
- 一方缺轮次时，只能在主体、类别、事件类型相同、日期邻近，且去除媒体后缀后的
  规范化标题一致时合并；
- 两方都存在明确轮次时，轮次集合必须有交集；没有交集时不合并。

日期只用于判断两个候选是否可能属于同一事件，不写回事件事实。

### 5.4 三目标预算覆盖

弹性规划顺序调整为：

1. 对所有合格候选按事件指纹去重；
2. 优先选择首次未覆盖的事件；
3. 最多覆盖 `verification_max_targets`，生产配置仍为 3；
4. 只有没有其他合格事件时，才允许重试已覆盖事件；
5. 达到连续无新增阈值的事件立即停止，不占用后续预算。

晋升潜力优先级：

1. 只缺网页发布日期且来源为 A/B 的候选；
2. 只缺一个严格证据字段、且存在明确官方或独立 B 来源线索的候选；
3. 只缺网页发布日期的 C 级线索；
4. 同时缺日期、金额或多个证据字段的候选；
5. 已多次无新增或存在证据冲突的候选。

规划器不再使用硬编码的“两目标覆盖”条件，而是严格服从
`verification_max_targets`。

### 5.5 来源等级感知的事件来源选择

`select_search_candidates` 增加可选的已登记高等级域名集合。流水线从现有融资来源配置
传入该集合。

同一搜索事件的主来源排序改为：

1. 官方发现来源；
2. 已登记的 A/B 域名；
3. 其他来源；
4. 在同一等级内再比较发布时间、相关性和 URL。

补充来源选择顺序：

1. 与主来源不同的已登记 B 级域名；
2. 其他不同域名；
3. 同域名补充页面。

仍保持补充来源数量上限，避免扩大正文抓取和模型分析成本。

本轮仅在融资独立媒体配置中新增：

```text
chinaventure.com.cn
```

投中网单源仍只能 pending。只有当投中网与另一已登记独立 B 级来源，例如
`pedaily.cn`，在目标主体、事件类型、融资轮次、金额披露状态和发布日期等严格字段上
相互一致时，才允许走现有“双独立 B 来源”晋级分支。

### 5.6 严格核验保持不变

以下规则不变：

- 采购、招中标类事件必须来自 A 级官方来源；
- 融资事件可由 A 级官方公司或投资机构来源单源核实；
- 没有 A 级来源时，必须有两个独立 B 级域名；
- 两个 B 级页面必须分别通过页面可用、主体、类别、事件类型、日期、融资字段和逐字
  证据检查；
- 搜索摘要、候选日期和 C 级转载只能决定检索方向，不能参与最终事实拼接。

本轮目标是让真实页面已有的合格事实进入现有严格规则，不修改规则结论。

### 5.7 候选诊断

`candidate-diagnostics.json` 增加两个精简字段：

- `publication_date_source`
- `verification_event_key`

字段用途：

- `publication_date_source` 解释日期来自元数据、JSON-LD、可见文头还是不存在；
- `verification_event_key` 解释哪些 URL 被视为同一弹性核验事件。

诊断仍不保存网页正文、模型原始输出、提示词、异常消息、Secrets 或 webhook。

## 6. 数据流

1. 发现通道完成基础 12 次搜索并产生候选。
2. 候选选择按事件分组，优先保留官方或已登记 B 级来源。
3. 抓取器获取网页，分别提取正文和严格页面发布时间证据。
4. 分析器使用事件主体上下文判断境内外，并从同页文本提取结构化事实。
5. verifier 执行首次严格核验。
6. pending 候选按统一事件指纹去重并计算晋升潜力。
7. 弹性预算优先覆盖最多 3 个不同事件；每次搜索后立即抓取、分析和重新核验。
8. 同一事件若形成官方 A 单源或两个独立 B 来源，进入 verified；否则保持 pending。
9. 报告、research trace 和 candidate diagnostics 写入 Artifact。

## 7. 错误与降级

- 未找到可信文头时间：保持日期缺失，不使用候选日期替代。
- 文头出现多个日期：只接受明确发布标签或最高优先级发布元数据；存在冲突时保持
  pending 并记录 `publication_date_conflict`。
- 主体上下文同时出现境内外主体且无法确定事件主语：保持分类待核实，不强行判定境内。
- 事件指纹字段不足：退回 URL 级目标，不把不同事件强行合并。
- 两个 B 级来源字段冲突：保持 pending，沿用现有 corroboration conflict 原因。
- 某一事件连续无新增：停止该事件并把剩余预算转移到其他合格事件。
- 新增投中网页面不可访问或证据不完整：仍按普通 pending 处理，不因域名登记而绕过
  正文核验。

## 8. 测试

### 8.1 页面发布时间

- `article:published_time`、`datePublished` 和 JSON-LD 继续生效。
- 投中网 `.releaseTime` 结构中的完整日期被保留。
- 带“发布日期”的公告标题区日期被保留。
- 普通 `time[datetime]` 只有处于文章标题或署名上下文时才被接受。
- 更新时间、页脚、相关推荐和正文历史日期不能成为文章发布日期。
- 抓取后的日期证据能够被分析器逐字 grounding。

### 8.2 境内主体

- 北京商业航天企业融资长文后部提到 SpaceX，仍判定为境内事件。
- 国外企业融资文章仅把中国作为市场背景时，仍判定为境外。
- 标题与导语主体冲突时保持待核实。
- RuleFallbackAnalyzer 与 verifier 分类一致性检查使用相同主体上下文。

### 8.3 事件指纹与预算

- “北京光邮星空科技有限公司”和“光邮星空”映射为同一主体。
- “Pre-A 和 Pre-A+”的多种标题顺序映射为同一融资事件。
- 同主体不同月份、不同轮次且事实不邻近的融资不合并。
- 三次预算在存在三个合格事件时依次覆盖三个事件。
- 只有一个或两个事件时才允许把剩余预算用于重试。
- 连续无新增达到阈值后不再重试该事件。

### 8.4 来源选择与严格晋级

- 同事件中较新的 C 来源不能挤掉 `pedaily.cn` 或
  `chinaventure.com.cn`。
- 投中网单源仍保持 pending。
- 投中网与投资界两个独立 B 页面事实一致时产生
  `verified_financing_two_independent_sources`。
- 两个 B 页面日期、金额披露状态或轮次冲突时不能晋级。
- 搜索摘要和搜索日期不能补齐任一严格字段。

### 8.5 诊断与回归

- 诊断展示日期证据来源和事件指纹。
- 同事件多个 URL 展示相同事件指纹。
- 诊断不包含正文、模型输出或敏感信息。
- 基础不超过 12、弹性不超过 3、总计不超过 15。
- 完整离线测试、`git diff --check` 和 workflow 安全检查通过。
- workflow 仍仅支持手动触发并强制 `--dry-run`。

## 9. 验收标准

代码验收：

- 真实结构等价的投中网页面文头时间进入页面证据；
- 国内主体不会因后文 SpaceX 对比被错误判为境外；
- 同一融资事件不同 URL 使用同一个核验事件指纹；
- 三个合格事件存在时，三次弹性预算不会重试同一事件；
- 已登记 B 来源优先于 C 级转载；
- 投中网单源不能晋级；
- 投中网与投资界两页事实一致的离线端到端用例严格晋级；
- 所有既有严格核验和安全边界测试保持通过。

真实运行验收：

- Artifact 显示基础 12、弹性不超过 3、总计不超过 15；
- `candidate-diagnostics.json` 能解释页面日期来源和事件合并；
- 弹性预算覆盖不同事件，或明确说明没有其他合格事件；
- `events.jsonl` 或 `financings.json` 至少产生 1 条符合现有严格门槛的
  `verified`；
- 如果真实公开来源变化导致仍为 0，Artifact 必须精确显示剩余事实或来源缺口，不能用
  搜索日期、C 级单源或放宽规则伪造成功；
- Actions success 仍不能替代上述业务验收。
