# 航天日报最小直连定时推送设计

## 目标

参考已稳定运行的“AI日报”项目，缩短 GitHub Actions 从定时触发到情报采集及钉钉投递之间的前置链路，并减少调度配置反复变化带来的不确定性。

本次改造只调整调度和生产运行前置步骤，不修改信息源、搜索预算、核实标准、AI 摘要、日报模板或钉钉投递内容。

## 调度设计

- 在实际执行生产采集与钉钉投递的 `.github/workflows/daily-intelligence.yml` 中直接保留定时配置。
- 每天只设置一个 cron：`50 23 * * *`，即北京时间 07:50。
- 删除北京时间 08:20 的备用 cron。
- 不引入中间调度 workflow、外部定时器或 Codex 定时任务。
- 手动 `workflow_dispatch` 入口及其 `dry_run`、`dingtalk_test`、`dingtalk_live` 模式保持不变。

GitHub Actions 的 schedule 不提供分钟级送达保证。因此验收目标是消除仓库内可控的延迟与复杂性，而不是承诺钉钉在 07:50:00 到达。

## 生产执行链路

定时任务按以下顺序执行：

1. 拉取仓库代码。
2. 配置 Python 及 pip 缓存。
3. 执行既有生产分支与重复投递保护。
4. 安装生产依赖 `pip install -e .`。
5. 运行既有情报采集、核实、报告生成和钉钉投递流程。
6. 发布运行摘要并上传成功或失败诊断产物。

完整测试不再作为每日定时生产运行的前置步骤。开发修改仍必须在提交前于本地运行完整测试；测试失败时不得提交生产改动。

## 内容质量不变项

以下业务能力不得因本次改造发生变化：

- 日常发现模式和搜索查询预算。
- 博查、DeepSeek 及正文抓取链路。
- 严格已核实、高可信待核实与候选线索的判定标准。
- 融资新闻与招标采购的硬性分类和字段展示。
- DeepSeek Flash 摘要及钉钉短报模板。
- 事件去重、投递去重、降级报告与异常告警。
- 钉钉签名、返回值校验和现有 Secrets 使用方式。
- 成功报告、失败诊断和运行结果 Artifact。

生产依赖必须完整覆盖运行时所需包。删除的是 pytest 等开发依赖的每日安装与测试执行，不得删除采集和生成日报所需的依赖。

## 失败处理

- GitHub 未按 07:50 创建运行时，不用第二 cron 掩盖问题；通过 Actions 的 `created_at`、`run_started_at` 和报告投递时间定位调度层延迟。
- 流程启动后失败时，沿用现有降级快报或异常告警规则。
- 重复运行保护继续生效，避免人工运行和定时运行在同一天造成重复正式推送。
- 不修改 Secrets、仓库可见性或 workflow 启停状态。

## 验证与验收

实施后必须满足：

1. `daily-intelligence.yml` 只有一个 schedule cron，换算后为北京时间 07:50。
2. schedule 直接启动实际生产 job。
3. 定时生产 job 不执行完整 pytest 测试。
4. 生产运行只安装生产依赖。
5. 手动三种投递模式继续存在，默认仍为 `dry_run`。
6. 本地完整测试全部通过。
7. YAML 可被正常解析，定时环境仍映射为 `daily`、既有查询预算和 `dingtalk_live`。
8. 改造提交推送到默认分支后，不再为观察效果反复改动定时声明。

次日通过 GitHub Actions 运行记录和钉钉消息共同验收实际表现。若 GitHub 创建运行明显晚于 07:50，则记录为平台调度延迟；若创建及时但投递较晚，则根据各步骤耗时继续优化生产执行链路。
