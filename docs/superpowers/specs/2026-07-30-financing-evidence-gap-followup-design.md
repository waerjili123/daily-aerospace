# 融资证据缺口定向核验设计

日期：2026-07-30
状态：已获用户书面复核确认
开发分支：`codex/verification-promotion-20260728`

## 1. 背景

提交 `4ed837b` 后的真实 dry-run Artifact 显示：

- 基础检索调用 12 次，弹性核验调用 0 次；
- 最终候选 5 条，严格已核实 0 条，待核实 4 条；
- 光邮星空投资界页面已从境内分类证据问题推进到
  `financing_missing_required_evidence`；
- 该原因不在弹性核验允许列表中，因此规划器没有执行
  `site:zgccity.com` 或其他证据补充查询；
- 页面同时出现“北京光邮星空科技有限公司”和“北京邮电大学”时，
  境内主体规则错误选择了更短的“北京邮电大学”；
- 当前融资证据失败原因过于笼统，研究轨迹无法说明究竟缺金额、轮次、
  日期还是投资方证据。

本轮问题不是弹性预算不足，而是证据缺口没有进入核验规划，以及查询缺少
字段级方向。

## 2. 目标

1. 允许 `financing_missing_required_evidence` 进入弹性核验候选池。
2. 确定性识别融资事实和逐字证据的具体缺口。
3. 根据缺口生成更有针对性的官方或独立来源查询。
4. 页面包含多个境内机构时优先选择融资企业主体。
5. 保持基础 12、弹性最多 3、总上限 15。
6. 不降低现有严格核验标准。

## 3. 非目标与安全边界

- 不允许两篇来源都省略金额时自动推定“金额未披露”。
- 不使用搜索摘要代替目标网页正文证据。
- 不使用搜索结果发布时间代替网页中可核验的发布日期。
- 不因命中官方域名直接晋升；官方页面仍需抓取、分析和逐字核验。
- 不改变来源等级要求、独立来源要求或事件合并规则。
- 不修改 Secrets、仓库可见性、workflow 启停或定时配置。
- 不设置 `dry_run=false`，不发送钉钉，不合并 PR。

## 4. 方案选择

采用确定性“证据缺口分类器”。

未采用的方案：

- 仅把新原因加入允许列表：虽然改动小，但查询仍然盲目，无法诊断预算浪费。
- 放宽金额门槛：虽然更容易产生已核实事件，但会把来源共同省略误当成事实，
  破坏已经确认的严格标准。

## 5. 组件设计

### 5.1 融资证据缺口

在严格核验模块中新增无副作用的字段级检查结果，至少覆盖：

- `organization`
- `published_at`
- `amount`
- `financing_round`
- `financing_subtype`
- `investors`

检查区分两类情况：

1. 结构化事实本身缺失；
2. 结构化事实存在，但缺少同页逐字证据。

字段是否必需继续完全沿用现有核验器：股权轮融资要求轮次，其他融资要求
融资子类型；只有结构化投资方非空时才要求投资方逐字证据。缺口分类器不会
额外创造新的必填字段。

金额采用现有严格语义：

- 有明确金额时，必须有金额逐字证据；
- 没有金额时，只有页面明确写出“未披露”等语句，才能形成
  `amount_disclosed=false` 及对应证据；
- 页面单纯省略金额时，仍然是缺口。

缺口分类器只解释现有核验结果，不改变核验结论。

### 5.2 核验原因与 Artifact

对外仍保留兼容的顶层原因 `financing_missing_required_evidence`，并在内部和研究
轨迹中增加有序字段列表，例如：

```json
{
  "trigger_reason": "financing_missing_required_evidence",
  "missing_evidence_fields": ["amount"]
}
```

pending 的原因继续保持稳定，避免破坏既有状态兼容；字段级缺口通过研究轨迹和
报告诊断输出。

### 5.3 弹性核验资格

将 `financing_missing_required_evidence` 加入允许定向核验的原因集合。

仍需满足现有资格：

- 状态为 `pending`；
- 境内、范围、类别和事件类型已确定；
- 主体存在；
- 页面发布日期或候选发布日期位于 90 天滚动池内；
- 未达到连续无新增停止阈值。

资格放开只允许查询，不会绕过后续抓取和严格核验。

### 5.4 缺口定向查询

查询生成器接收字段级缺口并增加确定性关键词：

- 缺 `amount`：`融资金额 金额未披露 具体金额 官方披露`
- 缺 `published_at`：`发布日期 公告时间`
- 缺 `financing_round`：`融资轮次 Pre-A Pre-A+`
- 缺 `investors`：`投资方 领投 跟投`
- 缺主体证据：主体全称与事件关键词

查询优先级保持：

1. 已登记官方企业或投资方域名的 `site:` 查询；
2. 投资方或公司官方披露查询；
3. 独立媒体交叉查询。

对光邮星空，候选摘要命中“中关村科学城”时，首个查询仍优先
`site:zgccity.com`，同时加入金额缺口关键词。搜索摘要只决定查询方向，
不写回事实。

### 5.5 境内融资主体优先级

同页多个境内机构按实体类型排序：

1. `股份有限公司`、`有限责任公司`、`有限公司` 等企业主体；
2. 公安局、军队单位、采购单位或明确项目主体；
3. 研究院、研究所、中心；
4. 大学。

同一优先级内选择最短、逐字存在的完整名称。规则只产生同页
`in_china` 引文，不覆盖已有非空主体字段。

### 5.6 停止和预算

- 基础检索预算仍为 12。
- 弹性核验预算仍最多为 3。
- 总调用硬上限仍为 15。
- 同一事件连续两次没有新增独立 URL 后停止。
- 历史 pending 已累计 1 次无新增时，本次只允许再尝试 1 次。
- 若另有合格目标，剩余预算可转移；否则保留未使用预算。

## 6. 数据流

1. 基础检索、候选选择、抓取和分析保持不变。
2. 严格核验返回顶层状态和原因。
3. 对融资待核实结果，缺口分类器读取同一分析结果和同页证据，输出字段列表。
4. 规划器根据资格、官方线索、字段缺口和预算选择下一查询。
5. 搜索结果进入现有候选筛选、抓取、分析、事件合并和严格重新核验链路。
6. 研究轨迹记录查询前缺口、命中别名、官方域名、查询后状态和停止原因。
7. 找不到缺口证据时保持待核实。

## 7. 错误与降级

- 缺口分类器无法确定具体字段：保留顶层原因，使用现有通用官方查询。
- 官方域名查询无结果：计入无新增，不生成事实。
- 搜索 API 失败：记录失败原因，不把错误结果当作证据。
- 官方页面不可抓取：记录抓取失败，不使用摘要替代正文。
- 新来源仍省略金额：保持 `financing_missing_required_evidence`。
- 主分析与确定性分类冲突：保持现有精确分类失败原因，不补证据。

## 8. 测试

### 8.1 缺口分类

- 金额存在且有逐字证据时不报告金额缺口。
- 明确写“金额未披露”时不报告金额缺口。
- 页面只省略金额时报告 `amount`。
- 轮次、日期和投资方分别缺失时输出相应字段。
- 分类器不改变分析结果或核验状态。

### 8.2 查询

- `financing_missing_required_evidence` 可以触发弹性核验。
- 光邮星空摘要命中中关村科学城时生成 `site:zgccity.com`。
- 金额缺口查询包含金额和未披露关键词。
- 未登记别名不能猜测官方域名。
- 搜索摘要不能写回金额、日期或投资方。

### 8.3 主体

- 同页同时出现“北京光邮星空科技有限公司”和“北京邮电大学”时选择前者。
- 只有大学时仍可选择大学作为境内机构证据。
- 引文必须逐字存在于同一页面。

### 8.4 流水线与回归

- 本次 Artifact 对应文本能够进入弹性核验。
- 研究轨迹记录 `missing_evidence_fields`。
- 连续无新增停止、目标切换和分配标签保持正确。
- 基础不超过 12、弹性不超过 3、总调用不超过 15。
- 单一 B 级来源、C 级转载和搜索摘要仍不能晋升。
- 完整离线测试和 `git diff --check` 通过。
- workflow 仍只允许手动触发并强制 `--dry-run`。

## 9. 验收标准

代码验收：

- Artifact 中的光邮星空候选可被识别为金额证据缺口；
- 该候选可以进入弹性核验并优先生成 `site:zgccity.com` 查询；
- 同页境内证据优先选择“北京光邮星空科技有限公司”；
- 找不到明确金额或“未披露”证据时仍保持待核实；
- 研究轨迹可解释调用方向和停止原因；
- 所有预算与安全边界保持不变。

真实运行验收：

- 弹性核验实际调用不超过 3，总调用不超过 15；
- 官方查询及字段缺口出现在 Artifact 研究轨迹中；
- 官方或独立来源必须经过正文抓取和逐字核验；
- 目标仍为至少 1 条符合既有严格标准的 `verified`；
- Actions success 不能替代业务验收。
