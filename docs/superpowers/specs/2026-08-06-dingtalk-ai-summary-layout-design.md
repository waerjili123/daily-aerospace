# 钉钉短报换行与 AI 摘要设计

## 目标

修复钉钉融资条目字段挤在同一行的问题，将原始搜索摘要改为 AI 事实摘要，并删除
“完整采集与诊断见 GitHub Artifact。”技术尾注。

## 模型边界

生产管道只允许 `deepseek-v4-flash`。页面分析、事实摘要、智能检索规划和项目匹配建议
全部使用 Flash；删除 `pro_model` 配置和所有 `deepseek-v4-pro` 生产引用。事实摘要复用
页面分析的同一次请求，不增加 API 调用次数。

## 摘要字段

`AnalysisResult` 增加 `brief_summary`：

- 使用中文、自己的话，40–80 字为目标，硬上限 120 字；
- 说明主体发生了什么，并在原文明确披露时包含金额/规模、用途或当前状态；
- 不使用外部知识，不推断缺失事实；
- 不复制网页第一段或搜索摘要；
- AI 缺失或失败时，只根据已经提取的结构化字段生成事实句，不回退展示搜索摘要。

该字段随候选诊断、严格融资记录和采购事件保存。同一融资事件合并时优先保留最新非空
摘要。

## 钉钉排版

融资条目使用固定的逐行格式：标题、企业、时间、轮次、金额、摘要、来源各自独占一行。
采购条目的摘要继续独占一行，但内容改用 `brief_summary`；缺失时使用结构化采购事项句。
所有字段继续使用 Markdown 子项目，以适配钉钉移动端。

系统状态只保留检索数、候选数、严格已核实数和覆盖状态，删除 Artifact 尾注。

## 验收

- 报告测试检查企业、时间、轮次、金额和摘要之间存在实际换行；
- 检查候选不会把原始搜索摘要直接写入短报；
- 检查 AI 摘要在 Flash 分析请求中产生并持久化；
- 检查代码、配置和测试中不存在 `deepseek-v4-pro`；
- 检查短报中不存在 Artifact 技术尾注；
- 完整测试与真实 dry-run 通过后再上线 `main`。
