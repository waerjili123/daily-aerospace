# 钉钉短报与融资/招标硬性分区设计

## 目标

钉钉正文必须让读者在一分钟内看清“商业航天融资新闻”和“招标采购情况”，
两类事件独立展示、独立统计、互不混算。技术诊断继续保留在 Artifact 的 JSON
数据中，不占用业务短报篇幅。

## 业务边界

### 商业航天融资新闻

仅包含目标商业航天企业的股权融资、战略融资、产业基金增资和并购融资。
每条按证据允许的范围显示：

- 融资日期；
- 企业；
- 轮次或融资类型；
- 明确披露的金额；
- 投资方；
- 业务或资金用途；
- 可信状态；
- 一个或多个可点击来源。

项目预算、中标金额、采购合同额不得作为融资金额；招股、股价和板块行情不进入
融资新闻。

### 招标采购情况

仅包含激光通信、激光武器/反无人机和光电转塔/吊舱相关的采购意向、招标、
询价、比选、变更、候选人、中标、废标和终止信息。每条显示项目日期、项目名称、
采购方、当前状态、明确金额、有效截止期和原始公告链接。

聚合站和搜索摘要只能标为候选线索；取得并核验官方采购原文后才能显示为严格
已核实。

## 钉钉短报结构

固定顺序如下：

1. 标题、统计截至时间和一行摘要；
2. `商业航天融资新闻`；
3. `招标采购情况`；
4. `其他行业动态`；
5. 有具体事项时才显示 `重点跟进`；
6. 一行 `系统状态`。

融资板块和招标板块都允许同时展示严格已核实、高可信待核实和候选线索，但必须
使用以下标签：

- `【已核实·今日新增】`
- `【已核实·历史补录】`
- `【高可信待核实】`
- `【候选线索】`

同一事件只展示一次。融资新闻优先于招标信息排序；每个板块最多三条，整份短报
目标长度为 600—1200 个中文字符，绝对上限继续受 `report.max_chars` 保护。

## 压缩规则

- 不原样发送搜索摘要；压缩为不超过 80 个字符的事实句。
- 删除网页模板、联系方式、公司通用介绍、行业背景和重复标题。
- 多个空分类合并到“其他行业动态”，不连续输出多个空板块。
- 没有可执行事项时隐藏“重点跟进”。
- `commercial_space_financing`、`budget_exhausted`、缺失字段代码、采集漏斗、
  失败域明细和模型轮次不得进入钉钉业务正文。
- 系统状态只显示候选数量、已核实事件数量和覆盖正常/降级；完整诊断继续保存在
  `data/` Artifact。

## 链接与可信度

- 严格已核实事件必须有可追溯来源。
- 多来源融资保留最多两个最有价值的独立来源链接。
- 招标优先显示官方原始公告；只有聚合线索时明确标注“聚合线索”。
- 不生成或猜测不存在的链接。
- 高可信待核实和候选线索不得使用“已核实”措辞。

## 时间口径

- 今日新增按报告时窗判断。
- 本轮发现但事件日期早于时窗的严格事件标记为“历史补录”。
- 融资新闻以近 7 天优先，使用 90 天滚动池补充稀疏期信息。
- 招标采购继续使用 90 天滚动池，并突出仍可报名或即将截止的项目。

## Artifact 与安全边界

`reports/YYYY-MM-DD.md` 保存与钉钉一致的短报；完整候选、诊断、采集漏斗和研究
轨迹继续由 `data/` 文件保存并随 Artifact 上传。失败兜底、投递回执和
`delivery_mode` 语义保持不变。

本次不修改 Secrets、仓库可见性或 workflow 启停状态，不启用定时任务，不合并
PR，也不执行真实钉钉推送。
